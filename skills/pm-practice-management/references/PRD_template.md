# Skill PRD 模板

每个新 skill 项目前，PM 先用此模板定义需求。

```markdown
# Skill: {名称} — 产品需求文档

## 问题定义
{谁在什么场景下有什么痛点，2-3 句}

## 目标用户
{主要用户、次要用户、非目标用户}

## 输入与输出
| 项目 | 说明 |
|------|------|
| 输入 | 用户提供什么？ |
| 输出 | 生成什么？ |
| 触发方式 | slash command / API / 自动 |

## 验收标准（Acceptance Criteria）
| # | 标准 | 验证方式 | 优先级 |
|---|------|---------|--------|
| 1 | {标准描述} | {如何验证} | P0 |
| 2 | {标准描述} | {如何验证} | P1 |

## 非目标（Out-of-Scope）
{明确不做什么，防止 scope creep}

## 使用限制
{已知限制，用户须知}
```

## 编写原则

1. **P0 是红线**：不满足则不能发布，每条 P0 必须有明确的验证方式。
2. **P1 是重要但不阻塞发布**：可以后续迭代补上。
3. **P2 是有更好**：记录但不承诺。
4. **Out-of-Scope 比 In-Scope 更重要**：它是防止 scope creep 的唯一防线。
5. **问题定义不超过 3 句**：如果说不清楚问题，说明还没理解需求。
