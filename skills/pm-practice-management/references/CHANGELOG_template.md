# 版本日志

## 版本规范

| 版本位 | 变更类型 | 示例 |
|--------|---------|------|
| major | 行为或输出格式变化，不向后兼容 | v1.0 → v2.0 |
| minor | 新增能力，向后兼容 | v1.0 → v1.1 |
| patch | 修复 bug，无功能变化 | v1.1 → v1.1.1 |

## 日志格式

```markdown
## [版本号] - 日期

### Added
- {新功能}

### Changed
- {变更}

### Fixed
- {修复}

### Removed
- {移除}
```

## 原则

1. **每次发布强制更新**：版本日志不更新的项目，三个月后没人知道当前是什么版本。
2. **同步打 Git tag**：每个版本对应一个 tag。
3. **记录对用户有影响的变更**：内部重构不需要记录，行为变化必须记录。
