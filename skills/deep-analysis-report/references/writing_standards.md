# 写作与呈现规范

## 1. 面向决策者写作

报告应像交给高管或决策者的简报：

- 先判断，后证据；
- 先影响，后数据；
- 先说结论边界，再说建议；
- 少解释系统如何工作；
- 不把表格堆成报告主体。

## 2. 禁止暴露内部过程口吻

避免：

```text
本节用于...
下表用于...
内部规则...
模型可判断...
为避免误读...
系统导出数据显示...
程序判断...
```

改写为：

```text
现有材料显示...
但仍缺少...
本期不宜进一步推断为...
该议题已进入...
后续需观察...
```

## 3. 避免教训式表达

少用"不是...而是..."这类像在教育读者的句式。可改为更直接的判断：

不推荐：

```text
该议题不是单纯竞争问题，而是治理兑现叙事。
```

推荐：

```text
该议题的关键影响在于，竞争格局已经与治理兑现压力绑定。
```

## 4. 数据进入正文的条件

详细数字只有在能改变判断时进入正文：

- 证明某议题热度异常；
- 证明某主体变化明显；
- 证明某风险虽声量低但关注度高；
- 证明某判断需要降级；
- 支撑专题研判或监测优先级。

完整指标和长数字串进入表格或附录，不在分析段落反复铺陈。

## 5. 表格使用边界

正文表格可用于：

- 格局矩阵；
- 议题清单；
- 风险信号评分；
- 专题研判判断；
- 证据对照；
- 验证分析。

每张正文表格前必须有分析段落，表格后应有一句共同指向、限制或下一步。不要让标题下面直接跟表格。

## 6. 建议写法

建议默认降级为：

- 决策参考；
- 监测建议；
- 补证方向；
- 核验清单；
- 专题准备。

谨慎使用：

- 立即行动；
- 公开回应；
- 具体部门派工；
- 明确责任主体。

在没有授权、法律依据或专家复核前，不输出可直接执行的话术。

## 7. 标题命名

标题应是读者可理解的问题域，不要是内部机制：

| 不推荐 | 推荐 |
|--------|------|
| 风险雷达 | 重点风险研判 |
| 数据剖面 | 支撑数据剖面 |
| 模型可判断/不可判断边界 | 判断边界 |
| 处置优先级 | 重点议题信号 |

标题下不要直接接表格；先给一段简短分析。

## 8. 精简原则

正文可删减的内容：

- 与判断无关的指标解释；
- 重复出现的补证需求；
- 内部规则说明；
- 表格字段换名但含义重复；
- 无证据支撑的"建议动作"；
- 能放附录的完整口径。

保留的内容：

- 决策判断；
- 影响对象；
- 关键证据；
- 判断边界；
- 监测和补证方向；
- 改变专题研判状态的条件。
