# 团队质量一致性操作指南

确保团队内多人使用本 skill 时输出标准一致、评分稳定、持续改进。

---

## 1. 设评估准则（Rubric）

一个好的评估准则是团队一致的基石：

**好准则的特征：**
- 每个门禁使用**二元判断**（通过/不通过）而非打分，或 A-E 五档，避免连续分数漂移
- 每项有明确的判定标准（写出来"什么算通过"）
- 附带典型正反示例

**准则迭代周期：**
```
v1.0 → 使用 2 周 → 校准会议 → v1.1 → 使用 4 周 → 校准 → v2.0
```

---

## 2. 定期校准

### 启动校准

新团队或新准则启用时：

1. 准备 5 份覆盖好/中/差等级的输出样本
2. 每人独立评分，不讨论
3. 逐门禁对比评分差异
4. 分差 >1 级的门禁重点讨论标准理解
5. 修正准则措辞，记录改进日志

### 定期校准

| 团队成熟度 | 校准频率 | 样本数 |
|-----------|---------|--------|
| 新组建 | 每周 | 3-5 |
| 运行 1 个月 | 每两周 | 3-5 |
| 运行 3 个月+ | 每月 | 2-3 |

---

## 3. 快速一致性校验

在没有时间开正式校准会议时，可以使用简化流程：

```
1. 每次检查前，快速回顾过往 3 次检查中最常分歧的门禁项
2. 对当前输出中可能出现同样分歧的部分预先做注释
3. 如果发现新分歧，记录但不阻塞交付，留到下次校准
```

---

## 4. 分歧处理流程

```
两人评分分歧
  -> 确认是否影响交付（P0/P1 分歧需立即解决）
  -> 第三人独立评分
  -> 取中位数或多数意见
  -> 分歧项记录到准则改进日志
  -> 在下一次校准会议讨论
```

---

## 5. 质量基线迭代

### 基线建立

1. 团队共同评审 5-10 份典型历史输出，按当前准则评分
2. 取平均值作为"当前基线"
3. 设定改进目标（如"下季度基线提升一个等级"）

### 趋势追踪

每两周记录一次数据：

| 周期 | 平均等级 | P0/P1 数 | 校准会议 | 准则版本 |
|------|---------|---------|---------|---------|
| W1-2 | B | 3 | 是 | v1.0 |
| W3-4 | B | 2 | 是 | v1.1 |
| W5-6 | B+ | 1 | 否 | v1.1 |

## 7. 团队分工建议

| 角色 | 职责 | 建议配置 |
|------|------|---------|
| 准则负责人 | 维护准则版本、主持校准会议、仲裁分歧 | 1 人（senior/tech lead） |
| 评审者 | 执行日常质量检查 | 全员 |
| 基线管理员 | 维护质量基线数据、追踪趋势 | 1 人（可兼） |
| 改进推动者 | 推动准则改进落地 | 全员 |

---

## 8. 常见陷阱

| 陷阱 | 表现 | 解法 |
|------|------|------|
| 准则膨胀 | 门禁越来越多，检查越来越繁重 | 每季度审视准则，删除低价值门禁 |
| 标准漂移 | 同样的内容在不同时间评分不同 | 固定准则版本，校准会议定期对齐 |
| 过度工程 | 花在检查上的时间超过生成时间 | 快速检查即可，高利害内容才走完整检查 |
| 批评性不足 | 习惯性给"通过" | 校准会议中使用"最严格者"先发言 |
